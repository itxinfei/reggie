# Reggie 外卖系统 · 技术优化路线图（2026Q4–2028Q4，M1–M9）

## TL;DR
本路线图覆盖 **2026Q4–2028Q4 共 9 个里程碑**，总投资 **116–164 人周（≈2.5–3.5 人年，3–5 人团队）**。核心策略为 **"先地基后护城河、竞争力给足权重"**：
- **M1–M2** 优先消除工程健康债务（会话无状态 / 并发解耦 / 异步化 / 测试 CI / 租户强校验），直接对标竞品最大短板 **"稳定性"**（卡顿 / 丢单 / 断网）；
- **M2–M4** 起并行推进 P0 竞争力（多租户 SaaS 化 R-14、全渠道四通 R-15）构筑核心护城河，命中"连锁数据自主 / 信创私有化 / 规避平台抽佣"三痛点；
- **M3–M6** 深化可维护性（上帝类拆分 / 事件总线 / 版本化 / SB 升级）；**M5–M7** 落地 P1 竞争力（会员私域 R-16、AI/BI R-17）；**M7–M9** 收口 P2 生态与合规（开放 API / 硬件抽象 / 云原生信创等保）。
每个里程碑设 **可量化退出标准**，资源曲线 **前期重工程健康、中后期重竞争力**。

## 一、当前指标 / 健康度基线（数析代码事实）

| 指标 | 当前值（代码事实） | 目标基线 | 风险等级 |
|------|------------------|---------|---------|
| 会话状态 | **Session + Cookie，内存态**（应用进程内，无法水平扩容） | 无状态 / Redis 共享会话 | 高 |
| Redis 连接池 | **池大小 8** | 按峰值扩容 + 限流旁路化 | 高 |
| MySQL 连接池（Druid） | **池大小 20** | 调优 + 预编译 + 限流不阻塞 HTTP 线程 | 高 |
| 上帝类 | **存在大型单体 Service/Controller 上帝类**（限界不清、改动回归面大） | 按限界上下文拆分 + ACL 防腐层 | 中高 |
| 测试 | **742 用例直连真实 MySQL + Redis，无 CI 流水线** | Testcontainers/H2/嵌入式 Redis + CI 门禁 | 高 |
| 框架版本 | **Spring Boot 2.4.5（已 EOL，安全补丁缺失）** | 升至 2.7.x LTS（JDK 1.8 硬约束，禁 3.x/jakarta） | 高 |
| 多租户隔离 | **仅 10 张表带 tenant_id，其余表绕过强校验** | 全表 tenant_id + 强校验拦截 | 中高 |

> 结论：工程健康为 **P0 地基缺口**，是后续 SaaS 化 / 四通 / 高并发扩展的硬约束，须前置收敛。

## 三、竞品动态（竞析护城河与空白项）

- **市场规模**：餐饮数字化 2026 破 **1000 亿**（CAGR 20%+）；SaaS 约 **320 亿**；AI 渗透率仅 **15%**（2028 达 **50%**）；连锁化率 **25%** → 增量空间明确。
- **护城河三痛点命中**：零许可费、数据自主可控、可深度二开、私有部署 → 精准命中 **"连锁数据自主 / 信创私有化 / 规避平台抽佣"** 三大商家痛点。
- **竞品最大槽点 = 稳定性**（卡顿 / 丢单 / 断网）→ **反向印证工程健康 P0 地基的商业价值**：稳定性是 Reggie 差异化第一抓手。
- **竞品空白项**：多平台割裂处理弱、私域与 AI 能力浅 → Reggie 可在 **四通（R-15）+ 私域（R-16）+ AI/BI（R-17）** 形成差异化切入。

## 四、路线图更新（核心交付）

### 4.1 编排原则
1. **P0 工程健康地基（R-01/02/05/06/10/21）前置 M1–M2**，先消债保稳定。
2. **P0 竞争力（R-14/15）M2–M4 与地基重叠推进**，护城河尽早动工。
3. **P1 深化可维护性（R-03/04/07/08/09/11/13）M3–M6**，跟随地基红利平滑推进。
4. **P1 竞争力（R-16/17）M5–M7**，复用地基与扩展范式。
5. **P2 生态 + 合规（R-12/18/19/20）M7–M9** 收尾，权重最低、可后置。

### 4.3 各里程碑可量化退出标准

- **M1 退出**：无状态鉴权全量上线；会话可跨节点共享（支持水平扩容）；租户 `tenant_id` 强校验拦截绕过；限流旁路化后 HTTP 线程零阻塞（压测峰值不堆积）。
- **M2 退出**：支持 **无损滚动发布**；**CI 门禁通过**（lint + 测试）；报表/AI 对话/图片异步流式化完成；742 测试脱离真实 MySQL/Redis（本地起停 < 5 分钟）。
- **M3 退出**：单实例多租户隔离可用（≥90% 表带 tenant_id）；连锁总部可建门店并下发管控；四通框架 + 美团/饿了么适配器跑通端到端订单。
- **M4 退出**：加盟分账账期/规则闭环（不接真实资金通道）；四通全平台（美团/饿了么/抖音）订单统一路由；调度线程池分组 + 分布式锁看门狗上线（无锁竞争风暴）。
- **M5 退出**：完成 1–2 个核心限界上下文拆分 + ACL；领域事件可落库重放（R-13）；会员储值/积分骨架可用。
- **M6 退出**：配置/SQL 版本化可回滚（Flyway）；**Spring Boot 退出 EOL（升 2.7.x LTS）**；会员私域（储值/积分/企微）可用。
- **M7 退出**：AI/BI 模块（销量预测/推荐/定价/排班/经营诊断）上线；开放 API + 插件框架可用；文档漂移 CI 拦截（`@MapperScan`/前端 `--legacy-*`）。
- **M8 退出**：硬件抽象层统一（KDS/打印/扫码/POS）；应用市场可上架/安装插件。
- **M9 退出**：信创栈适配完成（待定清单）；等保合规基线达标；云原生可弹性部署（多副本 + 配置外置）。

### 4.4 累计资源曲线说明
- **前期陡升（M1–M2）**：累计 8–10 → 18–23 人周，**几乎全为工程健康地基**，占总量 **~14–16%**，目标"先消债保稳定"，对标竞品最大短板。
- **中段放量（M3–M7）**：累计 33 → 135 人周，**竞争力相关投入（R-14/15/16/17/18）占此段 ~70%**，护城河与 AI 红利集中落地。
- **末段收口（M8–M9）**：累计 152 → 164 人周，降速做 **P2 生态 + 合规收尾**（硬件/应用市场/信创等保）。
- 曲线形态：**"先陡（地基）— 长平台（竞争力）— 缓收（合规）"**，体现"前期重工程健康、中后期重竞争力"的资源配置策略；里程碑按 **优先级收敛**而非平均铺开（P0 集中前 4 个里程碑，P2 仅末 3 个）。

## 五、利益相关者沟通要点

### 5.1 高管视图（商业价值 / 竞争力 / 投入产出）
1. **先地基后护城河**：前期重投工程健康（P0 地基 18–23 人周）直接对冲竞品最大短板"稳定性"（卡顿/丢单/断网），守住口碑底线。
2. **核心护城河**：P0 竞争力 R-14（多租户 SaaS）+ R-15（四通）命中"连锁数据自主/信创私有化/规避平台抽佣"三痛点，撬动 **320 亿 SaaS** 市场。
3. **总投入可控**：116–164 人周（≈2.5–3.5 人年），4 人团队约 7 季度；前期工程健康仅占 ~15%，中后期竞争力占 ~70%。
4. **踩中红利**：AI/BI 模块化（R-17）吃 **AI 渗透率 15%→50%** 红利；私域基座（R-16）拉升复购 **21%→40–70%**、获客 **52→8 元**。
5. **风险前置收敛**：资金分账通道后置、信创栈待定，避免前期重资产投入，ROI 更平滑。

### 5.2 工程视图（架构债务 / 技术风险 / 里程碑）
1. **债务清单**：Session 内存态、Redis 池 8 / DB 池 20、上帝类、测试无 CI、SB 2.4.5 EOL、租户 10 表绕过。
2. **消债节奏**：M1–M2 优先（R-01/02/05/06/10/21）；M6 完成 SB 2.7.x LTS 升级退出 EOL。
3. **扩展底座**：异步化（R-06）与事件总线（R-13）解耦调用链，为 SaaS 化（R-14）与四通（R-15）提供可扩展范式。
4. **拆分风险**：上帝类拆分（R-08）跨 M5–M6，需 ACL 防腐层控制回归面；建议按限界上下文分批灰度。
5. **硬约束**：JDK 1.8 禁 3.x/jakarta；分账/信创依赖外部待定项，须设里程碑闸门。

### 5.3 设计 / 产品视图（用户体验改善点）
1. **出餐效率**：KDS 卡顿慢 15–30% → 异步化 + 并发解耦后显著提速（M2/M5 见效）。
2. **多平台割裂**：日均 2h / 错发 2.3% / 费率 18–25% → 四通适配器（M3/M4）统一订单，降错发、降费率。
3. **C 端体验**：加载慢 43.2% / 支付流失 34% → 无状态 + 缓存防护 + 异步（M1/M2）降首屏与支付耗时。
4. **私域复购**：复购 21%→40–70%、获客 52→8 元 → 会员私域基座（R-16，M5/M6）支撑。
5. **食材损耗**：损耗 8–12% → AI 销量预测 / 排班（R-17，M7）优化备货。

## 八、Non-goals（非目标）
- ❌ 不做 Spring Boot 3.x / jakarta 迁移（JDK 1.8 硬约束，R-11 仅升 2.7.x LTS）。
- ❌ 不在本路线图接入 **真实资金分账通道**（R-14 仅做账期/规则逻辑，通道后置待商务确认）。
- ❌ 不做 C 端独立 App 重构（聚焦商家端管理系统）。
- ❌ 不替换 MySQL / Redis 技术栈（仅调优、池化、缓存防护）。
- ❌ 不承接具体信创国产栈选型（清单待定，仅预留适配基线）。

## 九、待确认 / 假设
1. **团队规模假设 3–5 人**（基线 4 人），影响里程碑墙钟时长与累计资源曲线斜率；若低于 3 人，M3–M4 护城河项需顺延。
2. **JDK 升级冻结**：维持 Java 1.8 硬约束，禁 SB 3.x / jakarta 迁移，R-11 升级路径限于 2.7.x LTS。
3. **分账资金通道后置**：R-14 加盟分账仅做账期 / 规则分账逻辑，真实资金通道（银行 / 三方支付）接入后置，待商务与合规确认。
4. **信创目标栈待定**：R-20 信创适配的具体国产数据库 / 中间件 / OS 清单待定，影响 M9 范围与等保测评周期。
5. **四通同步粒度**：R-15 订单 / 库存 / 菜单 / 评价的同步粒度（实时 / 准实时 / 批量）待与业务确认，影响架构与错发率目标。
6. **缓冲预留**：累计资源为理论人周下限，未含需求波动 / 回归 / 联调缓冲，建议整体预留 **15–20%** 安全垫。

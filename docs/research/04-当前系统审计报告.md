## 二、代码质量审计

### 2.1 整体架构评分

| 维度 | 评分 | 说明 |
|------|:----:|------|
| 分层架构 | ★★★★ | Controller → Service → Mapper 清晰 |
| 代码复用 | ★★★☆ | Common/Utils 抽取良好，部分重复 |
| 命名规范 | ★★★★ | 整体符合 Java 命名规范 |
| 注释覆盖 | ★★★★ | 核心逻辑有注释，部分关键决策缺说明 |
| 异常处理 | ★★★☆ | 有统一异常处理，但部分 catch 块为空 |
| 日志规范 | ★★★★ | 使用 SLF4J，有脱敏、有性能监控 |
| 依赖管理 | ★★★★ | Maven 依赖清晰，版本统一管理 |
| 配置管理 | ★★★☆ | application.yml 集中管理，部分硬编码 |

### 2.2 各层代码质量

#### Controller 层

**做得好**：
- ✅ 统一的 `R` 返回对象封装
- ✅ 分页查询使用 `Page` 对象规范
- ✅ 参数校验基本覆盖（`@PathVariable`、`@RequestBody`）
- ✅ 事务管理 `@Transactional` 标记清晰

**待改进**：
- ⚠️ 部分接口缺少参数校验注解（`@Valid`/`@NotNull` 等）
- ⚠️ 少数 Controller 直接拼接 SQL 条件（应移到 Mapper）
- ⚠️ Controller 中有业务逻辑（应下沉到 Service）
- ⚠️ 接口响应格式不统一（部分返回 null 而非空列表）

#### Service 层

**做得好**：
- ✅ 使用了 MyBatis Plus 的 LambdaQueryWrapper，避免字符串拼接
- ✅ 原子操作使用 `synchronized` 或数据库锁
- ✅ 库存扣减有并发控制意识

**待改进**：
- ⚠️ 部分 Service 方法是"透传"Mapper（无业务逻辑）
- ⚠️ 缺少 DTO/VO 分层，Entity 直接返回前端（暴露数据库结构）
- ⚠️ 部分事务边界不合理（读操作加了事务）
- ⚠️ 没有接口层抽象（直接依赖实现类）

#### Mapper 层

**做得好**：
- ✅ 使用 MyBatis Plus，SQL 基本由框架生成
- ✅ 自定义 SQL 使用 `#{}` 防注入
- ✅ 分页基本规范

**待改进**：
- ⚠️ 少数 XML 中使用 `${}`（动态排序/分组字段需校验）
- ⚠️ 缺少慢查询监控
- ⚠️ 部分关联查询应使用 ResultMap 而非多次查询

## 三、安全审计

### 3.1 安全机制清单

| 安全机制 | 状态 | 评分 | 说明 |
|----------|:----:|:----:|------|
| SQL注入防护 | ✅ 已实现 | ★★★★ | MyBatis #{} + 参数校验 |
| XSS防护 | ⚠️ 部分 | ★★★ | 前端有v-html，后端部分未转义 |
| CSRF防护 | ✅ 已实现 | ★★★★ | Token机制 |
| 密码加密 | ✅ 已实现 | ★★★★ | BCrypt/Spring Security |
| 暴力破解防护 | ✅ 已实现 | ★★★★★ | 登录失败锁定+IP限制 |
| 接口限流 | ✅ 已实现 | ★★★★ | 自定义注解+AOP |
| 日志脱敏 | ✅ 已实现 | ★★★★★ | LogMaskUtils手机号等脱敏 |
| 认证授权 | ✅ 已实现 | ★★★★ | Session/Redis + Filter |
| 文件上传安全 | ⚠️ 部分 | ★★★ | 无文件类型白名单校验 |
| CORS安全 | ⚠️ 部分 | ★★★ | 配置过于宽松 |
| 敏感信息泄露 | ⚠️ 部分 | ★★★ | Entity直接返回前端 |
| 输入校验 | ⚠️ 部分 | ★★★ | 缺少@Valid统一校验 |

### 3.2 高风险项

| # | 风险 | 风险等级 | 影响 | 修复建议 |
|:--:|------|:------:|------|----------|
| 1 | Entity直接序列化返回前端 | 🔴 高 | 暴露表结构、敏感字段 | 增加DTO/VO层 |
| 2 | CORS配置过于宽松 | 🔴 高 | CSRF攻击风险 | 限制Origin白名单 |
| 3 | 文件上传无类型校验 | 🔴 高 | 可上传WebShell | 增加MIME白名单 |
| 4 | Token存储在localStorage | 🟡 中 | XSS可窃取Token | httpOnly Cookie |
| 5 | 部分接口无权限校验 | 🟡 中 | 越权访问 | 完善Filter白名单 |
| 6 | 错误信息暴露内部细节 | 🟡 中 | 信息泄露 | 统一错误响应 |

### 3.3 安全加固建议（按优先级）

```
P0 (立即修复)：
  1. 文件上传增加 MIME 白名单校验(jpg/png/gif/pdf 等)
  2. CORS Origin 改为可配置白名单
  3. Entity 增加 @JsonIgnore 或 VO 层隔离

P1 (本周修复)：
  4. Token 改为 httpOnly Secure Cookie
  5. 统一输入校验(@Valid + 自定义Validator)
  6. 错误信息脱敏

P2 (计划修复)：
  7. 敏感配置上 Nacos/Vault
  8. HTTPS 强制(生产环境)
  9. Content-Security-Policy 头
```

## 五、数据库设计审计

### 5.1 表设计问题

| 问题 | 影响 | 建议 |
|------|------|------|
| 部分表缺少创建/更新时间 | 无法追踪数据变更 | 统一增加 `create_time`/`update_time` |
| 部分JSON字段存大文本 | 查询效率低 | MySQL 8.0用JSON类型 |
| 订单表设计单薄 | 无法支撑复杂场景 | 拆分为订单头+订单行+支付流水 |
| 食材表无批次/效期字段 | 成本核算不准确 | 增加批次表和效期表 |
| 缺少归档策略 | 数据量增长后性能下降 | 订单按月归档 |
| 索引缺失 | 慢查询风险 | 为高频查询字段建索引 |

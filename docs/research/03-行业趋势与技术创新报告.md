## 一、2025-2026 餐饮行业宏观趋势

### 1.1 餐饮市场数据

| 指标 | 2023年 | 2024年 | 2025年(预测) | 趋势 |
|------|:------:|:------:|:------:|:----:|
| 全国餐饮收入(万亿) | 5.29 | ~5.6 | ~5.9 | ↗ 稳步增长 |
| 餐饮数字化渗透率 | 28% | 32% | 38% | ↗ 加速 |
| SaaS市场规模(亿) | ~180 | ~220 | ~270 | ↗ 年增20%+ |
| 连锁化率 | 19% | 21% | 24% | ↗ 万店时代 |
| 外卖占比 | 24% | 26% | 28% | ↗ 持续提升 |

### 1.2 五大宏观趋势

#### 趋势一：万店连锁时代
- 餐饮连锁化率突破24%，1000+门店品牌快速增长
- **需求**：多店统一管理、中央厨房、供应链标准化
- **瑞吉机会**：强化多店对比分析、中央厨房模块

#### 趋势二：全域经营（公域+私域）
- 商家从依赖平台到自建流量池
- **需求**：小程序点餐+会员管理+企业微信社群+直播带货
- **瑞吉机会**：小程序商城、私域会员运营

#### 趋势三：AI 全面渗透
- ChatGPT/大模型驱动餐饮智能化
- **需求**：智能客服、销量预测、自动排班、菜单优化
- **瑞吉机会**：AI智能补货、AI菜品推荐、AI经营分析

#### 趋势四："耕者有其田" — 去平台化
- 商家希望摆脱平台30%抽佣
- **需求**：自营外卖系统、聚合接单、低成本支付
- **瑞吉机会**：聚合外卖接单 + 自营外卖频道

#### 趋势五：极致性价比
- 消费者趋向理性，9.9元价格带火热
- **需求**：食材成本管控、采购比价、损耗分析
- **瑞吉机会**：成本管控模块（差异化核心）

#### 对瑞吉外卖的建议实施优先级

```
Phase 1 (立即)：
  → 菜单智能分析（ABC分类 + LLM解读）
  → 经营异常检测 + 自然语言报告

Phase 2 (1-2月)：
  → 菜品智能推荐（协同过滤 + 用户画像）
  → 智能补货建议（时序预测）

Phase 3 (3-6月)：
  → 销量预测（多特征模型）
  → 智能定价建议
```

### 2.2 WebSocket 实时通信

| 场景 | 技术方案 | 实现要点 |
|------|----------|----------|
| 新订单弹窗 | STOMP over WebSocket | 消息队列 → WebSocket广播 |
| 订单状态变更 | STOMP 点对点 | 按用户/角色推送 |
| 库存预警 | 定时巡检 + WebSocket推送 | 阈值触发 + 管理员推送 |
| 排队叫号 | WebSocket广播 + 语音TTS | 大屏轮播 + 语音播报 |
| 厨房KDS | WebSocket + 音效 | 分栏看板 + 超时变色 + 语音提醒 |

#### 技术选型建议

```
方案A：Spring WebSocket + STOMP + SockJS
  ├── 优点：原生集成，无需额外中间件
  └── 缺点：单机内存，多实例需额外处理

方案B：Spring WebSocket + RabbitMQ/Redis PubSub
  ├── 优点：支持分布式，消息可靠
  └── 缺点：增加组件依赖

推荐：方案A（当前阶段），未来迁移方案B
```

### 2.4 技术栈升级路径

| 组件 | 当前 | 建议升级 | 原因 |

| JDK | 8 | 17 LTS | 安全性+性能+新特性(Record/Sealed/Pattern Matching) |
| Spring Boot | 2.x | 3.2+ | Native支持+虚拟线程+可观测性 |
| MyBatis Plus | 3.x | 3.5+ | 稳定版+新功能 |
| 前端框架 | jQuery + Vue 2 | Vue 3 + Vite | 性能+生态+TS支持 |
| 构建工具 | Maven | Maven 3.9 | 稳定版 |
| 数据库 | MySQL 5.7 | MySQL 8.0 | 窗口函数+CTE+JSON增强 |
| 缓存 | Redis(有基础) | Redis 7 + Redisson | 分布式锁+布隆过滤器 |

| 搜索 | 无 | Elasticsearch | 菜品搜索+日志分析 |

## 四、政策与合规趋势

### 4.1 数据安全
- 《数据安全法》《个人信息保护法》对餐饮SaaS的合规要求
- 用户手机号/支付信息的加密存储
- 订单数据保留期限（建议至少3年）
- 数据跨境限制（如果未来扩展海外）

### 4.2 电子发票
- 金税四期全面推进
- 餐饮业全面推行电子发票
- 对接百望云/票通/唯你等发票服务商

### 4.3 食品安全
- 食材追溯要求（批次管理 + 效期管理）
- 明厨亮灶（后厨视频监控接入）— 可作为增值模块

## 五、总结与建议

### 5.1 技术层面的三个"必须做"

| # | 项目 | 为什么 |
|:--:|------|--------|
| 1 | **WebSocket 实时推送** | 没有实时通知就不是完整的外卖系统 |
| 2 | **数据驾驶舱重构** | 当前仪表盘太简陋，老板根本没法用 |
| 3 | **移动端H5/小程序** | 没有移动端等于放弃50%的使用场景 |

### 5.2 业务层面的三个"差异化"

| # | 项目 | 为什么 |
|:--:|------|--------|
| 1 | **AI智能补货** | 竞品还停留在规则引擎，用大模型降维打击 |
| 2 | **食材成本管控** | 哗啦啦做得太复杂，我们可以做轻量好用的版本 |
| 3 | **开源免费增值** | 降低获客成本，口碑传播，差异化竞争策略 |

### 5.3 一个"长期壁垒"

**开放API + App Marketplace**：让第三方ISV为瑞吉开发插件（如排班插件、发票插件），构建生态护城河。这是Toast验证过的成功路径。

### 1.2 架构痛点

| # | 痛点 | 影响 |
|:--:|------|------|
| 1 | 单体架构，所有模块耦合 | 改一个模块可能影响整体，部署必须全量 |
| 2 | 前端页面耦合（单HTML + 大JS） | 前端加载慢，修改风险高 |
| 3 | 无消息队列 | 异步任务（短信/通知/报表）阻塞请求线程 |
| 4 | Redis单机无高可用 | 宕机后Session/验证码全丢失 |
| 5 | 文件存储本地 | 无法水平扩展，无CDN加速 |
| 6 | 无API网关 | 所有流量打到应用服务器 |
| 7 | 无分布式能力 | 无法多实例部署 |

## 三、关键组件选型与升级

### 3.1 Java 升级路径 (JDK 8 → JDK 17)

```xml
<!-- pom.xml 变更 -->
<properties>
    <java.version>17</java.version>
    <spring-boot.version>3.2.0</spring-boot.version>
    <mybatis-plus.version>3.5.5</mybatis-plus.version>
</properties>
```

**注意事项**：
- `javax.*` → `jakarta.*` 包名变更
- Spring Security 配置类 API 变更
- Swagger → SpringDoc OpenAPI 迁移
- 需要 JDK 17 运行时环境

### 3.2 数据库升级 (MySQL 5.7 → 8.0)

```
收益：
  ✅ 窗口函数 (ROW_NUMBER/RANK/LEAD/LAG) → 数据分析查询大幅简化
  ✅ CTE (WITH RECURSIVE) → 树形分类查询不再需要递归代码
  ✅ JSON 类型增强 → 订单扩展字段等场景
  ✅ 不可见索引 → 安全删索引
  ✅ 降序索引 → 列表排序更快
  ✅ 原子 DDL → 更安全的表变更

风险：
  ⚠️ 认证插件变更 (mysql_native_password → caching_sha2_password)
  ⚠️ GROUP BY 严格模式
  ⚠️ 保留字增加 (如 rank/lead/lag)
```

### 3.4 消息队列选型

| 选项 | 优势 | 劣势 | 适合场景 |
|------|------|------|----------|
| RabbitMQ | 稳定、管理界面好、社区大 | 吞吐量一般 | 订单异步、通知推送 |
| RocketMQ | 阿里系、事务消息、顺序消息 | 运维复杂 | 分布式事务 |
| Redis Stream | 零额外组件 | 功能简单 | 轻量消息 |Proposal|

**建议**：Phase 1 不需要MQ，Phase 2 推荐 RabbitMQ

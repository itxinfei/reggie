## 📊 监控功能

### Actuator 监控端点

#### 端点列表

| 端点 | 地址 | 说明 | 权限 |
|------|------|------|------|
| 健康检查 | `/actuator/health` | 应用健康状态 | 公开 |
| 应用信息 | `/actuator/info` | 应用版本、描述 | 公开 |
| 性能指标 | `/actuator/metrics` | JVM、CPU、内存指标 | 公开 |
| Prometheus | `/actuator/prometheus` | Prometheus 格式指标 | 公开 |
| 环境配置 | `/actuator/env` | Spring 环境信息 | 需认证 |

#### 配置说明

监控端点配置在 `application.yml` 中：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus,env
        base-path: /actuator
  endpoint:
    health:
      show-details: when-authorized
      show-components: always
  metrics:
    export:
      prometheus:
        enabled: true
    tags:
      application: ${spring.application.name}
    distribution:
      percentiles-histogram:
        http.server.requests: true
        http.client.requests: true
```

2. 导入 Grafana Dashboard（推荐 ID: `4701` - Spring Boot 2.1 System Monitor）

3. 配置告警规则：

```yaml
groups:
  - name: reggie_alerts
    rules:
      - alert: HighMemoryUsage

        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "内存使用率超过 85%"
```

### 日志配置

#### 日志文件位置

| 日志文件 | 路径 | 保留时间 | 说明 |
|---------|------|---------|------|
| 全部日志 | `logs/reggie.log` | 30天 | 滚动日志 |
| 错误日志 | `logs/reggie-error.log` | 90天 | 用于告警 |
| 控制台输出 | - | - | 开发环境 |

#### 日志级别

| 环境 | 日志级别 | 输出位置 |
|------|---------|---------|
| dev（开发） | INFO | 控制台 + 文件（异步） |
| prod（生产） | INFO | 文件（异步） |

#### 日志配置详解

日志配置在 `logback-spring.xml` 中：

```xml
<!-- 全部日志：30天滚动，最大1GB -->
<appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
  <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
    <fileNamePattern>${LOG_PATH}/${APP_NAME}.%d{yyyy-MM-dd}.log</fileNamePattern>
    <maxHistory>30</maxHistory>
    <totalSizeCap>1GB</totalSizeCap>
  </rollingPolicy>
</appender>

<!-- 错误日志：90天保留，最大500MB -->
<appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
  <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
    <fileNamePattern>${LOG_PATH}/${APP_NAME}-error.%d{yyyy-MM-dd}.log</fileNamePattern>
    <maxHistory>90</maxHistory>
    <totalSizeCap>500MB</totalSizeCap>
  </rollingPolicy>
</appender>
```

### API 性能监控

#### 监控特性

- 自动记录所有 Controller 接口响应时间
- 慢接口告警（>1秒）
- 记录接口方法和 URI

#### 实现原理

基于 AOP 切面 `ApiPerformanceMonitorAspect`，环绕所有 `com.reggie.controller` 包下的方法：

```java
@Around("execution(* com.reggie.controller..*(..))")
public Object monitorApiPerformance(ProceedingJoinPoint point) throws Throwable {
    long startTime = System.currentTimeMillis();
    Object result = point.proceed();
    long executionTime = System.currentTimeMillis() - startTime;
    logPerformance(point, executionTime);
    return result;
}
```

#### 日志示例

**正常接口：**

```
2026-07-02 09:14:32.123 [http-nio-8080-exec-1] DEBUG com.reggie.common.ApiPerformanceMonitorAspect - ✅ 接口性能正常 - 执行时间：45 ms, URI：/employee/page, 方法：EmployeeController.page()
```

**慢接口告警：**

```
2026-07-02 09:14:32.123 [http-nio-8080-exec-1] WARN  com.reggie.common.ApiPerformanceMonitorAspect - ⚠️ 慢接口告警 - 执行时间：1500 ms, URI：/order/page, 方法：OrderController.page()
```

#### 慢接口优化建议

1. **数据库查询慢**
   - 添加索引
   - 优化 SQL 语句
   - 使用分页查询

2. **接口逻辑复杂**
   - 异步处理非核心逻辑
   - 缓存热点数据

3. **外部调用慢**
   - 增加超时时间
   - 实现降级和熔断

## 🔐 安全功能

### API 限流保护

#### 限流策略

| 接口 | 限流阈值 | 限流类型 | 说明 |
|------|---------|---------|------|
| 员工登录 `/employee/login` | 5次/秒 | IP限流 | 防止暴力破解 |
| 用户登录 `/user/login` | 10次/秒 | IP限流 | 防止恶意登录 |
| 发送验证码 `/user/sendMsg` | 2次/秒 | IP限流 | 防止短信轰炸 |

#### 实现原理

基于 Redis 滑动窗口算法：

```java
// 增加计数器
Long count = redisTemplate.opsForValue().increment(limitKey);

// 首次设置过期时间（1秒）
if (count != null && count == 1) {
    redisTemplate.expire(limitKey, 1, TimeUnit.SECONDS);
}

// 判断是否超过限流阈值
if (count != null && count > rateLimit.maxRequestsPerSecond()) {
    throw new RuntimeException("请求过于频繁，请稍后重试");
}
```

#### 限流降级

如果 Redis 不可用，限流功能自动降级（不限制请求），保证服务可用性：

```java
// 检查 Redis 是否可用
if (!isRedisAvailable()) {
    log.warn("Redis 不可用，限流降级，直接放行");
    return point.proceed();
}
```

#### 限流日志

**限流触发：**

```
2026-07-02 09:14:32.123 WARN  com.reggie.common.RateLimitAspect - ⚠️ 接口限流触发 - 请求数：6/5，Key：rate_limit:com.reggie.controller.EmployeeController.login:192.168.1.100
```

**Redis 降级：**

```
2026-07-02 09:14:32.123 WARN  com.reggie.common.RateLimitAspect - Redis 不可用，限流降级，直接放行
```

#### 配置调整

如需调整限流阈值，修改 Controller 中的 `@RateLimit` 注解：

```java
// 员工登录：10次/秒
@RateLimit(maxRequestsPerSecond = 10, type = RateLimitType.IP)
@PostMapping("/login")
public R<Employee> login(...) { ... }
```

#### 自定义限流维度

| 类型 | 说明 | 使用场景 |
|------|------|---------|
| `RateLimitType.IP` | 按 IP 限流 | 防止暴力破解 |
| `RateLimitType.USER` | 按用户 ID 限流 | 防止账号滥用 |
| `RateLimitType.GLOBAL` | 全局限流 | 系统保护 |

### 暴力破解防护

#### 防护策略

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 最大失败次数 | 5次 | 超过则锁定 |
| 锁定时间 | 5分钟 | 锁定后需等待 |
| 失败计数有效期 | 15分钟 | 15分钟内的失败才累计 |
| 监控接口 | `/employee/login`, `/user/login` | 登录接口 |

#### 实现原理

基于 Redis 计数器：

1. **记录失败**：每次登录失败，失败计数器 +1
2. **检查锁定**：失败 >= 5 次，锁定 5 分钟
3. **重置计数**：登录成功后，清除失败计数
4. **降级处理**：Redis 不可用时，自动禁用防护

#### 日志示例

**失败记录：**

```
2026-07-02 09:14:32.123 INFO  com.reggie.common.BruteForceProtectionFilter - 登录失败 - 标识：admin, 失败次数：3/5
```

**账号锁定：**

```
2026-07-02 09:14:32.123 WARN  com.reggie.common.BruteForceProtectionFilter - ⚠️ 账号已被锁定 300 秒 - 标识：admin, 失败次数：5
```

**锁定拦截：**

```
2026-07-02 09:14:32.123 WARN  com.reggie.common.BruteForceProtectionFilter - ⚠️ 账号已被锁定 - 标识：admin
```

**降级提示：**

```
2026-07-02 09:14:32.123 WARN  com.reggie.common.BruteForceProtectionFilter - ⚠️ 暴力破解防护未启用（Redis不可用），自动降级
```

#### 手动解锁

如需手动解锁账号，使用 Redis CLI：

```bash
# 连接 Redis
redis-cli

# 删除锁定标记
DEL login:locked:admin

# 删除失败计数
DEL login:failure:admin

# 或批量删除
KEYS login:* | xargs DEL
```

#### 配置调整

修改 `BruteForceProtectionFilter.java` 中的常量：

```java
private static final int MAX_FAILED_ATTEMPTS = 5;        // 最大失败次数
private static final int LOCKOUT_DURATION = 300;         // 锁定时间（秒）
```

## ❓ 常见问题

### Q1: 监控端点返回 404

**原因：** Actuator 端点未配置或未暴露

**解决：**

1. 检查 `application.yml` 中的 `management.endpoints.web.exposure.include`
2. 确认访问地址：`http://localhost:8080/actuator/health`
3. 重启应用

### Q2: 限流不生效

**原因：** Redis 未启动或连接失败

**检查：**

1. 查看日志是否有 "Redis 不可用" 警告
2. 检查 Redis 连接配置：`spring.redis.*`
3. 测试 Redis 连接：`redis-cli ping`

**解决：**

- 启动 Redis 服务
- 检查 Redis 配置（host、port、password）

### Q3: 暴力破解防护未启用

**原因：** Redis 不可用导致自动降级

**解决：**

1. 查看日志：`⚠️ 暴力破解防护未启用（Redis不可用）`
2. 启动 Redis 服务
3. 验证 Redis 连接

### Q4: 日志文件过大

**解决：**

修改 `logback-spring.xml` 中的日志保留策略：

```xml
<!-- 缩短保留时间 -->
<maxHistory>7</maxHistory>  <!-- 7天 -->

<!-- 限制文件大小 -->
<totalSizeCap>500MB</totalSizeCap>
```

### Q5: 如何关闭性能监控

**方法：** 删除或禁用 `ApiPerformanceMonitorAspect` Bean

```bash
# 方法1：删除文件
rm src/main/java/com/reggie/common/ApiPerformanceMonitorAspect.java

# 方法2：添加 @Conditional 注解
```

### Q6: 监控数据采集失败

**检查项：**

1. **防火墙**：确保 `8080` 端口对外开放
2. **网络策略**：检查 Prometheus/Grafana 是否能访问
3. **认证配置**：如果启用了安全认证，需配置 Basic Auth

### Q7: 测试环境如何禁用监控

**方法：** 使用 Spring Profile 区分环境

```yaml
# application-dev.yml（开发环境）
management:
  endpoints:
    web:
      exposure:
        exclude: prometheus,env  # 开发环境排除部分端点
```

### Q8: 如何自定义告警规则

**步骤：**

1. 配置 Prometheus Alertmanager
2. 编写告警规则（`alerts.yml`）
3. 配置告警接收渠道（钉钉、企业微信、邮件等）

示例规则：

```yaml
groups:
  - name: reggie_security
    rules:
      - alert: BruteForceAttack
        expr: rate(login_failure_total[5m]) > 10
        labels:
          severity: critical
        annotations:
          summary: "检测到暴力破解攻击"
          description: "5分钟内登录失败次数超过10次"
```

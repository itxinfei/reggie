## 功能清单

### 1. CSRF 防护

**状态**: ✅ 已实现
**依赖**: 无（纯内存实现）
**文档**: [CSRF防护配置指南.md](./CSRF防护配置指南.md)

#### 核心特性

- **Token 生成**: 32字节随机数 + 时间戳
- **过期时间**: 1小时（可配置）
- **存储位置**: Session + Cookie + 响应头
- **验证策略**: GET 生成，POST/PUT/DELETE 验证
- **排除路径**: 登录、监控、静态资源等

#### 配置

**自动配置**，无需手动启用。

**排除路径**（`CsrfFilter.java`）:
```java
"/actuator/**",      // 监控端点
"/backend/**",       // 后台管理
"/front/**",         // 前端页面
"/common/upload",    // 文件上传
"/common/download",  // 文件下载
"/csrf/**",          // CSRF 接口
"/user/sendMsg",     // 发送验证码
"/user/login",       // 用户登录
"/employee/login"    // 员工登录
```

#### 测试

```bash
# CSRF 过滤器在测试环境自动禁用
mvn test -Dtest=CsrfTokenUtilTest
# ✅ 8 个测试用例
```

### 2. 暴力破解防护

**状态**: ✅ 已实现
**依赖**: Redis（可选，不可用时自动降级）
**文档**: [监控和安全使用指南.md](./监控和安全使用指南.md#暴力破解防护)

#### 核心特性

- **检测范围**: 员工登录、用户登录
- **最大失败次数**: 5 次
- **锁定时间**: 5 分钟
- **锁定维度**: IP 地址 + 用户名
- **统计粒度**: 全局计数

#### 配置

**常量配置**（`BruteForceProtectionFilter.java`）:
```java
MAX_FAILED_ATTEMPTS = 5   // 最大失败次数
LOCKOUT_DURATION = 300    // 锁定时间（秒）
```

**Redis Key 格式**:
- 失败计数: `login:failure:{ip_or_username}`
- 锁定标记: `login:locked:{ip_or_username}`

#### 生产环境配置

**application-prod.yml**:
```yaml
spring:
  redis:
    host: ${REDIS_HOST:localhost}
    port: ${REDIS_PORT:6379}
    password: ${REDIS_PASSWORD:}
```

#### 测试

```bash
mvn test -Dtest=BruteForceProtectionFilterTest
# ✅ 7 个测试用例
```

### 3. API 限流

**状态**: ✅ 已实现
**依赖**: Redis（可选，不可用时自动降级）
**文档**: [监控和安全使用指南.md](./监控和安全使用指南.md#api-限流)

#### 核心特性

- **算法**: Redis 滑动窗口
- **限流维度**: IP 地址（默认）
- **默认限制**: 1秒内最多 N 次请求

#### 使用方法

在 Controller 方法上添加 `@RateLimit` 注解：

```java
@RateLimit(maxRequestsPerSecond = 5)  // 1秒内最多5次
@PostMapping("/login")
public R<Employee> login(@RequestBody Employee employee) {
    // ...
}
```

#### 注解属性

```java
public @interface RateLimit {
    int maxRequestsPerSecond() default 10;  // 每秒最大请求数
    RateLimitType type() default RateLimitType.IP;  // 限流维度
    String keyPrefix() default "";           // Key 前缀
    boolean enabled() default true;          // 是否启用
}
```

#### 限流类型

- `IP` - 按 IP 地址限流（默认）
- `USER` - 按用户限流（TODO）
- `GLOBAL` - 全局限流

#### 已配置接口

**EmployeeController**:
- `POST /employee/login` - 5次/秒

**UserController**:
- `POST /user/login` - 10次/秒
- `POST /user/sendMsg` - 2次/秒

#### 测试

```bash
mvn test -Dtest=RateLimitAspectTest
# ✅ 4 个测试用例
```

### 4. 日志脱敏

**状态**: ✅ 已实现
**依赖**: 无
**文档**: 代码注释

#### 核心特性

- **手机号脱敏**: `13812341234` → `138****1234`
- **身份证脱敏**: `110101199001011234` → `110***********1234`
- **地址脱敏**: 保留前3字符，后续替换为 `***`

#### 使用方法

```java
import com.reggie.common.LogMaskUtils;

// 手机号脱敏
String masked = LogMaskUtils.maskPhone("13800138000"); // "138****8000"

// 身份证脱敏
String masked = LogMaskUtils.maskIdCard("110101199001011234"); // "110***********1234"

// 地址脱敏
String masked = LogMaskUtils.maskAddress("北京市朝阳区建国路88号"); // "北京市***"
```

#### 日志中使用

```java
// ✅ 正确：脱敏后再打印
log.info("用户登录，手机号={}", LogMaskUtils.maskPhone(phone));

// ❌ 错误：直接打印明文
log.info("用户登录，手机号={}", phone);  // 会被 SecurityAuditTest 检测到
```

#### 测试

```bash
mvn test -Dtest=LogMaskUtilsTest
# ✅ 3 个测试用例
```

## 生产环境建议

### 1. 强制启用 Redis

**原因**: Redis 不可用时，暴力破解和限流功能会自动降级。

**推荐配置**:
```yaml
spring:
  redis:
    host: ${REDIS_HOST}
    port: ${REDIS_PORT}
    password: ${REDIS_PASSWORD}
    lettuce:
      pool:
        max-active: 16
        max-idle: 8
        min-idle: 2
```

### 2. 启用 CSRF

**测试环境**: 自动禁用 ✅
**生产环境**: 自动启用 ✅

确保生产环境没有设置 `spring.profiles.active=test`。

### 3. 启用 HTTPS

**原因**: 防止中间人攻击，保护 Cookie 安全。

**配置**（Nginx 示例）:
```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 4. 启用监控和告警

**Prometheus + Grafana**:
```bash
cd monitoring
docker-compose up -d
```

**告警规则**（`monitoring/prometheus/alerts/reggie_alerts.yml`）:
- 应用宕机
- HTTP 错误率 > 5%
- API 响应时间 > 2秒
- JVM 内存使用率 > 85%
- 数据库连接池使用率 > 80%
- 登录失败率 > 10次/5分钟

### 5. 启用日志收集

**Loki（推荐，轻量级）**:
```bash
cd monitoring
docker-compose --profile logs up -d
```

**ELK（企业级）**:
```bash
cd monitoring
docker-compose --profile elk up -d
```

**检查项**:

## 常见问题

### Q1: CSRF 防护影响测试怎么办？

**A**: CSRF 过滤器在测试环境（`@Profile("test")`）自动禁用，无需手动处理。

如果需要在集成测试中启用 CSRF：
1. 移除 `@ActiveProfiles("test")`
2. 在请求中手动添加 CSRF Token

### Q2: Redis 不可用会有什么影响？

**A**:
- 暴力破解防护自动降级（不生效）
- API 限流自动降级（不生效）
- 应用正常运行，但失去防护能力

**建议**: 生产环境必须配置 Redis。

### Q3: 如何验证 CSRF 是否生效？

**A**: 使用 curl 测试：

```bash
# 1. 发送 GET 请求获取 Token
curl -c cookies.txt http://localhost:8080/employee/page?page=1

# 2. 提取 Token
TOKEN=$(grep XSRF-TOKEN cookies.txt | awk '{print $NF}')

# 3. 不携带 Token 发送 POST 请求（应该返回 403）
curl -b cookies.txt -H "Content-Type: application/json" \
  -d '{"username":"test"}' \
  http://localhost:8080/employee

# 预期: HTTP 403 Forbidden

# 4. 携带 Token 发送 POST 请求（应该成功）
curl -b cookies.txt -c cookies.txt -H "X-CSRF-TOKEN: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"test"}' \
  http://localhost:8080/employee

# 预期: HTTP 200 OK
```

### Q4: 登录失败次数在哪里查看？

**A**: Redis 中查看：

```bash
# 查看失败计数
redis-cli GET "login:failure:192.168.1.100"

# 查看锁定状态
redis-cli EXISTS "login:locked:192.168.1.100"
# 返回 1 = 已锁定，0 = 未锁定

# 手动解锁
redis-cli DEL "login:locked:192.168.1.100"
redis-cli DEL "login:failure:192.168.1.100"
```

### Q5: 如何调整限流阈值？

**A**: 修改 Controller 中的 `@RateLimit` 注解：

```java
// 将 5 改为你想要的值
@RateLimit(maxRequestsPerSecond = 5)
@PostMapping("/login")
public R<Employee> login() { ... }
```

### Q6: 监控看板看不到数据怎么办？

**A**:
1. 检查 Prometheus 是否正常运行: `http://localhost:9090/targets`
2. 检查应用是否暴露 `/actuator/prometheus` 端点
3. 检查防火墙规则
4. 查看 Prometheus 日志: `docker-compose logs prometheus`

### Q7: 日志脱敏规则在哪里配置？

**A**: `LogMaskUtils.java`，可以自定义脱敏规则：

```java
// 手机号：保留前3后4
phone.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2")

// 身份证：保留前3后4
idCard.replaceAll("(\\d{3})\\d{10}(\\d{4})", "$1***********$2")
```

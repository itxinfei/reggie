## 方案对比

| 特性 | Loki | ELK | 轻量级 ELK |
|------|------|-----|-----------|
| **资源占用** | 低 | 高 | 中 |
| **查询性能** | 快（仅索引元数据） | 慢（全量索引） | 中 |
| **存储成本** | 低 | 高 | 中 |
| **全文搜索** | 不支持 | 支持 | 支持 |
| **学习成本** | 低 | 高 | 中 |
| **适合场景** | 云原生、K8s | 企业级、复杂搜索 | 中型项目 |

**推荐选择**：
- **Loki**: 云原生环境，资源有限，只需日志查询
- **ELK**: 企业级，需要全文搜索和复杂分析
- **轻量级 ELK**: 中型项目，平衡功能和资源

## 方案一：Loki + Promtail + Grafana

### 架构

```
瑞吉外卖应用
    │
    │ 日志文件 (logs/*.log)
    ▼
Promtail (日志采集)
    │
    │ Push 日志
    ▼
Loki (日志存储)
    │
    │ 查询日志
    ▼
Grafana (日志可视化)
```

### 1. 配置 Logback 输出 JSON 格式

修改 `logback-spring.xml`，添加 JSON 格式的 appender：

```xml
<appender name="JSON_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>logs/reggie-json.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
        <fileNamePattern>logs/reggie-json.%d{yyyy-MM-dd}.log</fileNamePattern>
        <maxHistory>30</maxHistory>
        <totalSizeCap>1GB</totalSizeCap>
    </rollingPolicy>
    <encoder class="net.logstash.logback.encoder.LogstashEncoder">
        <includeContext>false</includeContext>
        <includeCallerData>false</includeCallerData>
        <fieldNames>
            <timestamp>timestamp</timestamp>
            <level>level</level>
            <thread>thread</thread>
            <logger>logger</logger>
            <message>message</message>
            <context>context</context>
        </fieldNames>
    </encoder>
</appender>

<root level="INFO">
    <appender-ref ref="JSON_FILE" />
</root>
```

需要在 `pom.xml` 添加依赖：

```xml
<dependency>
    <groupId>net.logstash.logback</groupId>
    <artifactId>logstash-logback-encoder</artifactId>
    <version>7.3</version>
</dependency>
```

### 2. Promtail 配置

创建 `promtail-config.yml`：

```yaml
server:
  http_listen_port: 9080
  grpc_listen_port: 0

positions:
  filename: /tmp/positions.yaml

clients:
  - url: http://loki:3100/loki/api/v1/push

scrape_configs:
  - job_name: reggie-takeout
    static_configs:
      - targets:
          - localhost
        labels:
          job: reggie-takeout
          __path__: /app/logs/reggie-*.log
    relabel_configs:
      - source_labels: [__filename__]
        regex: /app/logs/reggie-(.*)\.log
        target_label: app
        replacement: ${1}
```

### 3. Loki Docker Compose 配置

添加到 `monitoring/docker-compose.yml`：

```yaml
  # Loki 日志存储
  loki:
    image: grafana/loki:2.9.0
    container_name: reggie-loki
    ports:
      - "3100:3100"
    volumes:
      - ./loki:/etc/loki
      - loki-data:/loki
    command: -config.file=/etc/loki/loki.yml
    networks:
      - monitoring
    restart: unless-stopped

  # Promtail 日志采集
  promtail:
    image: grafana/promtail:2.9.0
    container_name: reggie-promtail
    volumes:
      - ./promtail:/etc/promtail
      - /var/log/containers:/var/log/containers:ro
      - /app/logs:/app/logs:ro  # 宿主机日志目录
    command: -config.file=/etc/promtail/promtail-config.yml
    networks:
      - monitoring
    restart: unless-stopped
    depends_on:
      - loki
```

### 4. Loki 配置

创建 `monitoring/loki/loki.yml`：

```yaml
auth_enabled: false

server:
  http_listen_port: 3100
  grpc_listen_port: 9096

common:
  instance_addr: 127.0.0.1
  path_prefix: /loki
  storage:
    filesystem:
      chunks_directory: /loki/chunks
      rules_directory: /loki/rules
  replication_factor: 1
  ring:
    kvstore:
      store: inmemory

query_range:
  results_cache:
    cache:
      embedded_cache:
        enabled: true
        max_size_mb: 100

schema_config:
  configs:
    - from: 2024-01-01
      store: tsdb
      object_store: filesystem
      schema: v13
      index:
        prefix: index_
        period: 24h

ruler:
  alertmanager_url: http://localhost:9093

limits_config:
  enforce_metric_name: false
  reject_old_samples: true
  reject_old_samples_max_age: 168h
```

### 5. 在 Grafana 中添加 Loki 数据源

1. 进入 Grafana → **Connections** → **Data sources**
2. 点击 **Add data source**
3. 选择 **Loki**
4. 设置 URL 为 `http://loki:3100`
5. 点击 **Save & Test**

### 6. 日志查询示例

在 Grafana Explore 中使用 LogQL 查询：

```
# 查询所有错误日志
{job="reggie-takeout"} |= "ERROR"

# 查询包含 "失败" 的日志
{job="reggie-takeout"} |= "失败" |~ "登录|订单"

# 统计错误日志速率
sum by (level) (count_over_time({job="reggie-takeout"} |= "ERROR" [5m]))
```

## 方案二：ELK Stack

### 架构

```
瑞吉外卖应用
    │
    │ 日志文件 (logs/*.log)
    ▼
Filebeat (日志采集)
    │
    │ Beats 协议
    ▼
Logstash (日志处理)
    │
    │ 解析和过滤
    ▼
Elasticsearch (日志存储和索引)
    │
    │ 查询
    ▼
Kibana (日志可视化)
```

### 1. Filebeat 配置

创建 `filebeat.yml`：

```yaml
filebeat.autodiscover:
  providers:
    - type: docker
      hints.enabled: true

filebeat.inputs:
  - type: log
    enabled: true
    paths:
      - /app/logs/*.log
    fields:
      application: reggie-takeout
      environment: production
    fields_under_root: true
    multiline.pattern: '^[0-9]{4}-[0-9]{2}-[0-9]{2}'
    multiline.negate: true
    multiline.match: after

processors:
  - add_docker_metadata: ~

output.logstash:
  hosts: ["logstash:5044"]
```

### 2. Logstash 配置

创建 `logstash.conf`：

```ruby
input {
  beats {
    port => 5044
  }
}

filter {
  if [fields][application] == "reggie-takeout" {
    # 解析 Spring Boot 日志格式
    grok {
      match => {
        "message" => "^%{TIMESTAMP_ISO8601:timestamp} \[%{LOGLEVEL:level}\] %{DATA:logger} : %{GREEDYDATA:log_message}"
      }
    }

    # 解析 JSON 字段
    json {
      source => "log_message"
      target => "json_fields"
      skip_on_invalid_json => true
    }

    # 添加标签
    mutate {
      add_field => {
        "service" => "reggie-takeout"
      }
    }

    # 提取异常信息
    if [level] == "ERROR" {
      grok {
        match => { "log_message" => "Exception: %{DATA:exception_class}" }
      }
    }
  }
}

output {
  elasticsearch {
    hosts => ["elasticsearch:9200"]
    index => "reggie-takeout-%{+YYYY.MM.dd}"
    user => "elastic"
    password => "${ELASTIC_PASSWORD}"
  }

  # 可选：输出到控制台用于调试
  # stdout { codec => rubydebug }
}
```

### 3. ELK Docker Compose 配置

添加到 `monitoring/docker-compose.yml`：

```yaml
  # Elasticsearch
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.11.0
    container_name: reggie-elasticsearch
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - "ES_JAVA_OPTS=-Xms512m -Xmx512m"
    ulimits:
      memlock:
        soft: -1
        hard: -1
    volumes:
      - elasticsearch-data:/usr/share/elasticsearch/data
    ports:
      - "9200:9200"
    networks:
      - monitoring
    restart: unless-stopped

  # Logstash
  logstash:
    image: docker.elastic.co/logstash/logstash:8.11.0
    container_name: reggie-logstash
    volumes:
      - ./logstash:/usr/share/logstash/pipeline
    environment:
      - ELASTIC_PASSWORD=changeme
    ports:
      - "5044:5044"
    networks:
      - monitoring
    restart: unless-stopped
    depends_on:
      - elasticsearch

  # Filebeat
  filebeat:
    image: docker.elastic.co/beats/filebeat:8.11.0
    container_name: reggie-filebeat
    volumes:
      - ./filebeat/filebeat.yml:/usr/share/filebeat/filebeat.yml:ro
      - /app/logs:/app/logs:ro
      - filebeat-data:/usr/share/filebeat/data
    environment:
      - ELASTIC_USER=elastic
      - ELASTIC_PASSWORD=changeme
    networks:
      - monitoring
    restart: unless-stopped
    depends_on:
      - elasticsearch

  # Kibana
  kibana:
    image: docker.elastic.co/kibana/kibana:8.11.0
    container_name: reggie-kibana
    ports:
      - "5601:5601"
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
    volumes:
      - kibana-data:/usr/share/kibana/data
    networks:
      - monitoring
    restart: unless-stopped
    depends_on:
      - elasticsearch

volumes:
  elasticsearch-data:
  filebeat-data:
  kibana-data:
```

### 4. Kibana 索引模式配置

1. 访问 http://localhost:5601
2. 进入 **Stack Management** → **Kibana** → **Index Patterns**
3. 点击 **Create index pattern**
4. 输入索引名：`reggie-takeout-*`
5. 选择时间字段：`@timestamp`
6. 点击 **Create**

### 5. 常用查询

在 Kibana Discover 中：

```
# 查询所有日志
_level: *

# 查询错误日志
_level: ERROR

# 查询包含 "失败" 的日志
message: 失败

# 按服务查询
service: "reggie-takeout"

# 组合查询
service: "reggie-takeout" AND _level: ERROR
```

## 方案三：轻量级方案（Logstash + Elasticsearch）

如果只需要 Elasticsearch 存储和查询，不需要 Kafka 等中间件：

### 1. Logback + Elasticsearch Appender

在 `pom.xml` 添加依赖：

```xml
<dependency>
    <groupId>com.integral</groupId>
    <artifactId>logback-elasticsearch-appender</artifactId>
    <version>1.0.0</version>
</dependency>
```

在 `logback-spring.xml` 配置：

```xml
<appender name="ELASTICSEARCH" class="com.integral.logback.ElasticsearchAppender">
    <url>http://elasticsearch:9200/_bulk</url>
    <index>reggie-takeout-%date{yyyy.MM.dd}</index>
    <maxBatchSize>1000</maxBatchSize>
    <flushTimeout>1000</flushTimeout>
    <encoder>
        <pattern>%d{ISO8601} [%thread] %-5level %logger{36} - %msg%n</pattern>
    </encoder>
</appender>

<root level="INFO">
    <appender-ref ref="ELASTICSEARCH" />
</root>
```

## 配置建议

### 开发环境

**推荐方案**: Loki + Promtail + Grafana

**理由**:
- 资源占用少
- 配置简单
- 与监控看板集成方便

### 生产环境

**推荐方案**: ELK Stack

**理由**:
- 功能完善（全文搜索、可视化、告警）
- 适合企业级日志管理
- 社区生态成熟

### 资源规划

| 方案 | CPU | 内存 | 磁盘 |
|------|-----|------|------|
| **Loki** | 1核 | 2GB | 50GB（30天） |
| **ELK** | 4核 | 8GB | 200GB（30天） |
| **轻量级 ELK** | 2核 | 4GB | 100GB（30天） |

### 日志保留策略

```yaml
# Loki 保留策略（在 loki.yml 中配置）
compactor:
  retention_enabled: true
  retention_delete_delay: 2h
  retention_delete_worker_count: 150

limits_config:
  retention_period: 720h  # 30天
```

```yaml
# Elasticsearch ILM 策略
PUT _ilm/policy/reggie-logs-policy
{
  "policy": {
    "phases": {
      "hot": {
        "min_age": "0ms",
        "actions": {
          "rollover": {
            "max_size": "50GB",
            "max_age": "1d"
          }
        }
      },
      "warm": {
        "min_age": "7d",
        "actions": {
          "forcemerge": {
            "max_num_segments": 1
          }
        }
      },
      "delete": {
        "min_age": "30d",
        "actions": {
          "delete": {}
        }
      }
    }
  }
}
```

## 常见问题

### 1. 日志采集失败

**问题**: Promtail/Filebeat 无法采集日志

**解决**:
- 检查日志文件权限
- 检查文件路径是否正确
- 查看 Promtail/Filebeat 日志

### 2. 日志延迟

**问题**: 日志有延迟

**解决**:
- 调整 `scrape_configs` 的 `scrape_interval`
- 检查网络延迟
- 增加采集并发数

### 3. 存储空间不足

**问题**: Elasticsearch/Loki 磁盘占满

**解决**:
- 配置日志保留策略
- 启用日志压缩
- 增加磁盘容量

## 架构概述

监控系统由以下组件组成：

```
┌─────────────────┐
│  瑞吉外卖应用    │
│  (Actuator +    │
│   Prometheus)   │
└────────┬────────┘
         │ HTTP /metrics
         ▼
┌─────────────────┐     ┌─────────────────┐
│   Prometheus    │────▶│    Grafana      │
│   (数据采集)     │     │   (数据可视化)   │
└─────────────────┘     └─────────────────┘
         │
         ▼
┌─────────────────┐
│   Alertmanager  │
│   (告警管理)     │
└─────────────────┘
```

### 端口说明

- **瑞吉外卖应用**: `http://localhost:8080/actuator/prometheus`
- **Prometheus**: `http://localhost:9090`
- **Grafana**: `http://localhost:3000`
- **Alertmanager**: `http://localhost:9093`

## Prometheus 配置

### 基础配置

创建 `prometheus.yml` 文件：

```yaml
global:
  scrape_interval: 15s # 每15秒采集一次
  evaluation_interval: 15s # 每15秒评估一次告警规则

# 告警规则文件
rule_files:
  - "/etc/prometheus/alerts/*.yml"

# 采集配置
scrape_configs:
  # Prometheus 自身监控
  - job_name: "prometheus"
    static_configs:
      - targets: ["localhost:9090"]

  # 瑞吉外卖应用监控
  - job_name: "reggie-takeout"
    metrics_path: "/actuator/prometheus"
    static_configs:
      - targets: ["host.docker.internal:8080"]
        labels:
          application: "reggie-takeout"
          environment: "production"
    scrape_interval: 10s
    scrape_timeout: 5s

  # MySQL 数据库监控 (可选)
  - job_name: "mysql"
    static_configs:
      - targets: ["host.docker.internal:9104"]
        labels:
          application: "mysql"
          environment: "production"

  # Redis 监控 (可选)
  - job_name: "redis"
    static_configs:
      - targets: ["host.docker.internal:9121"]
        labels:
          application: "redis"
          environment: "production"
```

### 告警规则

创建 `prometheus/alerts/reggie_alerts.yml`：

```yaml
groups:
  - name: reggie_takeout_alerts
    rules:
      # 应用宕机告警
      - alert: ApplicationDown
        expr: up{job="reggie-takeout"} == 0
        for: 1m
        labels:
          severity: critical
          application: reggie-takeout
        annotations:
          summary: "瑞吉外卖应用已宕机"
          description: "应用 {{ $labels.instance }} 已宕机超过1分钟"

      # HTTP 错误率过高
      - alert: HighErrorRate
        expr: |
          sum by (application) (
            rate(http_server_requests_seconds_count{job="reggie-takeout", status=~"5.."}[5m])
          ) /
          sum by (application) (
            rate(http_server_requests_seconds_count{job="reggie-takeout"}[5m])
          ) > 0.05
        for: 5m
        labels:
          severity: warning
          application: reggie-takeout
        annotations:
          summary: "HTTP 错误率过高"
          description: "应用 {{ $labels.application }} 的HTTP错误率超过5%"

      # API 响应时间过长
      - alert: HighResponseTime
        expr: |
          histogram_quantile(0.95,
            sum by (application, le) (
              rate(http_server_requests_seconds_bucket{job="reggie-takeout"}[5m])
            )
          ) > 2
        for: 5m
        labels:
          severity: warning
          application: reggie-takeout
        annotations:
          summary: "API 响应时间过长"
          description: "95%分位响应时间超过2秒"

      # JVM 堆内存使用率过高
      - alert: HighJvmMemoryUsage
        expr: |
          sum by (application) (
            jvm_memory_used_bytes{job="reggie-takeout", area="heap"}
          ) /
          sum by (application) (
            jvm_memory_max_bytes{job="reggie-takeout", area="heap"}
          ) * 100 > 85
        for: 5m
        labels:
          severity: warning
          application: reggie-takeout
        annotations:
          summary: "JVM 堆内存使用率过高"
          description: "JVM 堆内存使用率超过85%"

      # 数据库连接池使用率过高
      - alert: HighDatabaseConnections
        expr: |
         hikaricp_connections_active{application="reggie-takeout"} /
          hikaricp_connections_max{application="reggie-takeout"} * 100 > 80
        for: 5m
        labels:
          severity: warning
          application: reggie-takeout
        annotations:
          summary: "数据库连接池使用率过高"
          description: "数据库连接池使用率超过80%"

      # 登录失败率过高（可能遭受暴力破解）
      - alert: HighLoginFailureRate
        expr: |
          sum by (application) (
            rate(login_attempts_total{job="reggie-takeout", status="failure"}[5m])
          ) > 10
        for: 2m
        labels:
          severity: warning
          application: reggie-takeout
        annotations:
          summary: "登录失败率过高"
          description: "登录失败率超过10次/5分钟，可能遭受暴力破解攻击"
```

## Grafana 仪表板

### 导入仪表板

1. 打开 Grafana (http://localhost:3000)
2. 登录 (默认账号: `admin`, 密码: `admin`)
3. 点击左侧菜单 **Dashboards** → **Import**
4. 选择以下方式之一导入：

   **方式一**: 上传 JSON 文件
   - 点击 **Upload JSON file**
   - 选择 `grafana-dashboards/reggie-takeout-dashboard.json`
   - 点击 **Import**

   **方式二**: 使用仪表板 ID (如果已发布到 Grafana.com)

### 仪表板内容

Grafana 仪表板包含以下面板：

#### 1. 应用概览 (Application Overview)

- **请求速率 (RPS)**
  - 显示每秒请求数
  - 按 HTTP 方法分组 (GET/POST/PUT/DELETE)

- **错误率**
  - 4xx 错误率
  - 5xx 错误率
  - 按接口分组

- **响应时间**
  - P50 / P95 / P99 响应时间
  - 按接口分组

#### 2. 系统监控 (System Metrics)

- **JVM 内存使用**
  - 堆内存使用率
  - 非堆内存使用率
  - GC 次数和耗时

- **系统资源**
  - CPU 使用率
  - 内存使用率
  - 磁盘使用率

- **线程池状态**
  - 活跃线程数
  - 队列大小
  - 拒绝次数

#### 3. 业务监控 (Business Metrics)

- **订单统计**
  - 新增订单数/分钟
  - 订单完成率
  - 平均订单金额

- **用户活跃度**
  - 登录用户数
  - 注册用户数
  - 活跃会话数

- **数据库监控**
  - 连接池使用率
  - 慢查询数量
  - 查询响应时间

#### 4. 安全监控 (Security Metrics)

- **登录统计**
  - 登录成功率
  - 登录失败次数
  - 暴力破解检测

- **API 限流**
  - 被限流请求数
  - 限流原因分布

## Docker Compose 部署

创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  # Prometheus
  prometheus:
    image: prom/prometheus:v2.45.0
    container_name: reggie-prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - ./prometheus/alerts:/etc/prometheus/alerts
      - prometheus-data:/prometheus
    ports:
      - "9090:9090"
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.path=/prometheus'
      - '--storage.tsdb.retention.time=30d'
    networks:
      - monitoring
    restart: unless-stopped

  # Grafana
  grafana:
    image: grafana/grafana:10.0.0
    container_name: reggie-grafana
    volumes:
      - grafana-data:/var/lib/grafana
      - ./grafana/provisioning:/etc/grafana/provisioning
      - ./grafana/dashboards:/var/lib/grafana/dashboards
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
      - GF_USERS_ALLOW_SIGN_UP=false
    networks:
      - monitoring
    restart: unless-stopped
    depends_on:
      - prometheus

  # Alertmanager (可选)
  alertmanager:
    image: prom/alertmanager:v0.25.0
    container_name: reggie-alertmanager
    volumes:
      - ./alertmanager.yml:/etc/alertmanager/alertmanager.yml
    ports:
      - "9093:9093"
    networks:
      - monitoring
    restart: unless-stopped

volumes:
  prometheus-data:
  grafana-data:

networks:
  monitoring:
    driver: bridge
```

### 启动监控栈

```bash
# 启动所有服务
docker-compose up -d

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down

# 停止并删除数据
docker-compose down -v
```

### Grafana 预配置

创建 `grafana/provisioning/datasources/prometheus.yml`：

```yaml
apiVersion: 1

datasources:
  - name: Prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: true
```

创建 `grafana/provisioning/dashboards/dashboard.yml`：

```yaml
apiVersion: 1

providers:
  - name: 'Default'
    orgId: 1
    folder: ''
    type: file
    disableDeletion: false
    updateIntervalSeconds: 10
    allowUiUpdates: true
    options:
      path: /var/lib/grafana/dashboards
```

## 监控指标说明

### Spring Boot Actuator 内置指标

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `http_server_requests_seconds_count` | Counter | HTTP 请求总数 |
| `http_server_requests_seconds_sum` | Summary | HTTP 请求总耗时 |
| `http_server_requests_seconds_max` | Gauge | HTTP 请求最大耗时 |
| `jvm_memory_used_bytes` | Gauge | JVM 内存使用量 |
| `jvm_memory_max_bytes` | Gauge | JVM 最大内存 |
| `jvm_gc_pause_seconds` | Summary | GC 暂停时间 |
| `process_cpu_usage` | Gauge | CPU 使用率 |
| `system_cpu_usage` | Gauge | 系统 CPU 使用率 |

### 自定义指标

| 指标名 | 类型 | 说明 |
|--------|------|------|
| `login_attempts_total` | Counter | 登录尝试总数 (按状态分组) |
| `api_rate_limit_total` | Counter | API 限流次数 |
| `api_performance_seconds` | Timer | API 执行时间 |

## 告警配置

### Alertmanager 配置

创建 `alertmanager.yml`：

```yaml
global:
  smtp_smarthost: 'smtp.gmail.com:587'
  smtp_from: 'alerts@example.com'
  smtp_auth_username: 'alerts@example.com'
  smtp_auth_password: 'your-password'

route:
  receiver: 'email-notifications'
  group_by: ['alertname', 'application']
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h

receivers:
  - name: 'email-notifications'
    email_configs:
      - to: 'admin@example.com'
        send_resolved: true

  - name: 'webhook-notifications'
    webhook_configs:
      - url: 'http://your-webhook-endpoint/alerts'
        send_resolved: true

  - name: 'dingtalk-notifications'
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/robot/send?key=your-key'
        send_resolved: true
```

### 告警渠道

1. **邮件告警**: 发送邮件到运维邮箱
2. **Webhook 告警**: 调用内部告警系统
3. **钉钉/企业微信**: 发送到工作群
4. **短信告警**: 通过短信网关发送 (需要额外配置)

## 常见问题

### 1. 无法采集指标

**问题**: Prometheus 无法采集到指标

**解决**:
- 检查应用是否已暴露 `/actuator/prometheus` 端点
- 检查防火墙规则
- 在 `application.yml` 中确认 `management.endpoints.web.exposure.include` 包含 `prometheus`

### 2. Grafana 无法连接 Prometheus

**问题**: Grafana 显示 "Data source not found"

**解决**:
- 确认 Prometheus 服务正常运行
- 检查 Grafana 的 Prometheus 数据源配置 URL
- 在 Docker Compose 环境中使用服务名 `http://prometheus:9090`

### 3. 指标数据延迟

**问题**: 监控数据有延迟

**解决**:
- 调整 `scrape_interval` (默认15秒)
- 检查网络延迟
- 检查应用性能

### 4. 内存不足

**问题**: Prometheus 内存占用过高

**解决**:
- 减少 `scrape_interval`
- 缩短数据保留时间 (`--storage.tsdb.retention.time`)
- 增加服务器内存
